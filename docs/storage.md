# Blob storage
Storage of original documents. The contract lives in `uai_core.storage`; him
Concrete adapters live in the runtime. PostgreSQL preserves the metadata and the
provenance, not the blob; the vector index will be reconstructable from the data
authoritative.

## Contract

```python
class BlobStore(Protocol):
    async def put(self, key: str, data: bytes) -> None: ...
    async def get(self, key: str) -> bytes: ...
    async def delete(self, key: str) -> None: ...
```

- `new_blob_key(prefix)` generates a server-owned key (`prefix/<uuid hex>`).
- No endpoints or templates provide arbitrary URLs, paths or keys. The keys
  they are generated by the host and persisted in the document's metadata.
- Keys allow 1–8 ASCII components `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`.
  Absolute paths, `..`, `.`, empty components, backslashes, NUL, hidden names and
  keys over 512 characters are rejected with `ValueError`.
- `get` of an absent or non-regular key returns `BlobNotFound`; `delete`
  it is idempotent; backend errors are `BlobStoreError` with no details.

## Filesystem (default)

`FilesystemBlobStore(root)` uses `UAI_STORAGE_DIR` (default `data/blobs` in dev,
`/var/lib/uai/blobs` in Compose with volume `blob-data`).

- Writing occurs to a temporary file in the same directory, with
  `O_EXCL|O_NOFOLLOW`, `fsync` and `os.replace`: an interrupted upload does not appear
  complete and a reader sees the previous or new file.
- `O_NOFOLLOW` prevents following a trailing symlink; parents are resolved
  and they must remain under the root. The root must be controlled by the host.
- Cancellation is idempotent; temporary files are removed in case of
  error.
- The Docker volume is initialized with ownership of the runtime user, because the
  container is `read_only` with only the blob directory writable.

## S3-compatible (optional)

`S3BlobStore` uses `boto3` only if the adapter is instantiated. Addiction is not
in the base `requirements.txt`; install `apps/runtime/requirements-s3.txt` (or
equivalent in the secret manager) to enable it. `S3BlobStore.from_env()` reads:

| Variable | Mandatory | Notes |
| --- | --- | --- |
| `UAI_S3_BUCKET` | yes | operator provisioned bucket |
| `UAI_S3_ENDPOINT` | no | S3-compatible endpoint URL; absent for AWS |
| `UAI_S3_REGION` | no | default `us-east-1` |
| `UAI_S3_ACCESS_KEY` / `UAI_S3_SECRET_KEY` | couple | from secret manager; never logged in |
| `UAI_S3_PREFIX` | no | key prefix, validated |

PUT S3 is atomic per object; DELETE is idempotent. The bucket, the policy and the
credential are the host's responsibility. The endpoint never comes from
template content or non-administrative requests. Missing `boto3` produces
`BlobStoreUnavailable`.

## Fixtures S3

`compose.yaml` exposes the optional `s3` profile with RustFS (S3-compatible service
lightweight, local port, dedicated volume). It is not part of the core stack nor of
`make e2e`. Image pinned for digest; the default credentials are only
for the local fixture.

```bash
make storage-s3
```

The target starts RustFS on a free port, creates the bucket in the test, runs
`tests/test_storage.py` with `UAI_S3_TEST_ENDPOINT` and remove stack/volumes. The
fixture checks real PUT/GET/DELETE via boto3; without the target, the real S3 test
it was skipped and the tests with fake clients remain.

## Limits

- HTTP upload, MIME/size validation, hash/dedup and document metadata are
  implemented in M3-03 ([documents.md](documents.md)). Parser/chunking are
  M3-04/M3-05.
- The filesystem is not a distributed shared filesystem: only one runtime for
  volume, as in the current deployment.
- The root filesystem is trusted. The contract prevents final traversal and symlinks,
  but it does not defend against an attacker with arbitrary writing to the root host.
- No coordinated deletion with vector indices: will come with M3-09.## Evidence

`apps/runtime/tests/test_storage.py` covers absolute keys, traversals, paths,
symlink final/parent, partial upload, persistence, delete idempotent, adapter
S3 with fake client, `from_env` and a real roundtrip to RustFS. The endpoint
internal `PUT/GET/DELETE /internal/v1/storage/{key}` is covered by
`test_storage_api.py` is used by M3-03 document upload. Local evidence:
221 runtimes + 8 workers passed + 3 skipped with `make test`; 8/8 with `make storage-s3` (RustFS).
