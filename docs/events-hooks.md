# Lifecycle events and observational hooks

The system distinguishes two versioned contracts, with shared envelope in the core:

- `RuntimeEvent`: the four existing public SSE v1 events, with text for
  delta/completion and normalized code for error.
- `LifecycleEvent`: internal observations with metadata only; all 18 phases of
  section 6 of the specification have typed payloads. Separate JSON schema is
  `packages/api-contract/lifecycle.schema.json`, including the inter-phase constraint
  and payloads. It is not a new public endpoint or an additional SSE stream.

Each event carries event UUID, version 1, UTC timestamp generated by the runtime,
run_id and correlation_id. The observations of the four public events retain
the same event_id/timestamp, replacing the text with the character count.
The other events receive an identity of their own. No prompts, messages, topics
tool, tool result or memory content enters the observation contract.

## Phases actually issued

An accepted BasicAgent run produces, in order:

1. request.received: number of messages and input characters, including the prompt.
2. request.authorized: confirmation of the context received from the trusted caller.
3. agent.started.
4. context.building.
5. context.ready: counts after before_model.
6. model.before: Authorized model identifier.
7. response.delta: number of characters of each chunk.
8. model.after: total characters produced, before after_model validation.
9. response.completed, or agent.failed with normalized code.

An error interrupts the sequence at the stage reached. For example, a guard
mandatory failed during context.building prevents model.before and terminates
with agent.failed. A close/cancel observes agent.cancelled and propagates it
cancellation; does not attempt to write SSE to a closed connection. The closure
explicit of the provider occurs before returning control, even if its
generator is suspended after a delta. AgentRuntime retains responsibility for
clean the working memory.

The request events describe the already accepted run, after private authentication and
preflight: Don't invent persisted run IDs for HTTP 401/422 requests. The callbacks
initials are notified when the consumer resumes after the first frame
agent.started. A consumer who closes immediately can only see the notification
agent.cancelled; These observations are not frame delivery receipts.
They are not a substitute for auditing rejected HTTP requests from the gateway.

Tool and memory event are defined and validated in the contract, but are not issued
as dummy operations: they will be connected when the relevant paths exist
real. The runtime does not claim to have read the gateway database.

## Trusted registration

```python
from uai_runtime.app import from_env
from uai_runtime.hooks import HookRegistry, HookSubscriber

async def observe(event):
    # event is a detached, immutable, contentless snapshot of the model.
    pass

hooks = HookRegistry()
hooks.register(HookSubscriber(name='deployment.metrics', callback=observe,
                              priority=0, timeout_seconds=0.05))
app = from_env(hook_registry=hooks)
```

It's Python host composition, not installation via HTTP. `event_types` can be
a frozenset of only the desired phases. The registry rejects duplicate names,
invalid metadata and more than 64 subscribers. Each run acquires a selection
sorted by ascending priority, then name; Subsequent registrations are valid for
future runs. Callbacks are shared and must be reentrant.

Each subscriber receives a separate copy of the event and payload, both
frozen and with only scalars. No reference to ExecutionContext, authority,
limits, working memory or input is delivered. The returned values are
ignored: to modify context or impose policies use the directives pipeline,
with its mandatory guards and fail closed validation.## Timeouts, errors and limits

Delivery is async and sequential. The default timeout for subscriber is 50 ms;
the total observer budget is 1 second per run, shared among all
events. When it runs out, subsequent notifications are skipped and the first
jump is recorded. No queues or background tasks are left active.

Subscriber exceptions and timeouts are isolated, then the subscriber continues
next within budget. A CancelledError raised by the callback alone is
isolated; an actual cancellation of the calling task propagates. The logs contain
subscriber name, phase, run_id, correlation_id and reason; exclude exceptions,
contents and credentials. It's local diagnostics, not PostgreSQL transactional audit
or durable delivery guarantee.

Intermediate notifications also consume the run time limit; they can
therefore contribute to its global expiry. Terminal notification is external to
execution timeout, always within the observation budget residue: avoid one second
terminal during notification. You can add the remaining budget to the maximum
delivery latency. Agent.cancelled is also best effort within that budget;
a second deletion can break it. No new states are invented
persisted cancellations before M4-01.

Asyncio timeouts are cooperative. Callbacks that block the thread, suppress
deleting or executing hostile Python code requires process isolation,
not offered by this API.

## Compatibility and verification

The gateway continues to receive/persist only agent.started, response.delta,
response.completed and agent.failed. An internal metadata frame arrived in error
on the public channel it is rejected. EOF without terminal and SSE v1 replay remain
governed by the existing contract. No SQL migration required.

`test_hooks.py` covers order, filters, snapshot isolation, errors/timeouts,
budget, cancellation, mandatory guards, privacy and immediate closure of
provider. `test_contract.py` compares the generated lifecycle schema. The Go test
verifies the existing SSE boundary without introducing duplicate parsers.

The E2E factory registers a metadata sink only in the test runtime's tmpfs.
`check_hooks.py`, included in `make e2e`, checks sequence, terminals and absence of
new notifications in replays. Docker/PostgreSQL tested with `make e2e`;
local ASGI tests remain complementary.
